# Discord chat upgrade

Objective: interact with a local Codex thread from Discord, with complete progress and answers, visible work, useful media, and replies delivered to the same conversation.

## Stages

1. **Implemented — reliable transcript delivery.** Track assistant messages by item ID; schedule trailing updates; reconcile completed text; serialize Discord writes; preserve order and code blocks. Reproduce the single-character failure using fast event bursts.
2. **Implemented — verbose work.** Render exposed thinking summaries, command start/completion/output, file edits, searches, tool calls, plans and compaction independently of assistant prose. No extra Stop buttons; `/stop` remains available.
3. **Implemented — conversation controls.** Steer active turns with ordinary messages; accept native questions via buttons or typed replies; preserve full option values; disable stale controls. When `/autodecision on` is enabled (default: off), after five minutes explicitly ask Codex to select the most likely answer from context and continue. Keep tool permission approvals separate from feedback decisions.
4. **Implemented — media and artifacts.** Attach images explicitly viewed/generated by Codex and the latest turn diff; show bounded command output tails. Resolve files within the registered project and Codex image-output roots, enforce upload limits, deduplicate delivery and report unavailable assets.
5. **Automated checks implemented; live check pending — verification and documentation.** Replay complete protocol conversations through the app-server notification listener and Discord message handler, including rapid deltas, concurrent edits, thinking/tools, media, questions, fallback, steering, stopping, failures and session resumption. Run the full test suite, type checking and build.

## Acceptance checks

- A burst starting with `I` becomes the complete message while the turn is still running.
- Multiple commentary messages and the final answer remain separate and in event order.
- A command running after commentary remains visible, including available output and its outcome.
- Exposed reasoning summaries are shown; raw reasoning blocks are not forwarded.
- Images are attached once, and failures or size limits are visible.
- Typed replies and buttons return the original answer to the matching pending request.
- With auto-decision off, decisions wait for a human reply. Live toggles update pending question timers immediately.
- With auto-decision on, a five-minute fallback instructs Codex to choose; it does not submit an empty answer.
- Stopping or a resolved native request closes controls and clears timers.
- Discord transport failures are logged and retried without duplicate messages.
- The session-list length fix continues to pass its regression tests.

## Verification boundary

Automated replay uses the real event dispatcher, formatter and conversation controller with a simulated Discord transport. This proves message routing, content and ordering; a live Discord run is still required to verify permissions, Discord rate limits and the installed Codex version's actual event coverage. Do not describe automated replay as a live deployment test.

## Local verification

The synthetic fixture in `src/codex/fixtures/conversation.json` is replayed through the real JSON parser and event listener into the controller, formatter and simulated Discord transport. Separate message-handler tests check typed-answer routing and live feedback. Additional tests cover safe image roots, duplicate images, final-edit retry, stale controls, five-minute fallback, failed turns and session resumption. Existing session-list validation regressions remain in the suite.

After building, restart the bot with its usual launcher when the current task is idle. A live smoke check should:

1. Open `/sessions` and resume an existing thread.
2. Ask Codex to inspect files and run a command. Check that commentary, command/output updates and the final answer remain visible without Stop buttons.
3. Send feedback during a running task and confirm Codex acknowledges it in the same thread.
4. Ask for a required decision with two choices. Select one, then try a separate question with a typed answer. Verify `/autodecision off` keeps another question pending beyond five minutes; then enable `/autodecision on`, leave it unanswered for five minutes and verify Codex states its chosen answer and continues.
5. Ask Codex to review a project image and generate an image if supported by the installed Codex version. Check the uploaded images and final diff attachment.
6. Stop a pending question with `/stop`; confirm its controls close and no fallback resumes work later.

Live smoke checks have not been performed by this implementation session. No bot restart or live Discord messages are part of the automated checks.

## Activity detail preference

Activity summaries are compact by default (`DISCORD_VERBOSE=false`), with no shell command text or command output. Commentary, exposed thinking summaries, decisions, images and final answers remain available. Set `DISCORD_VERBOSE=true` only when detailed command diagnostics are wanted.
